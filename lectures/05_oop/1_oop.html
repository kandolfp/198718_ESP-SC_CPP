Programming paradigms 1/2

A programming paradigm can help translate a specific problem into code.

Imperative programming

The code directly determines/controls the flow of the execution and explicit statement changes the state of the program.

  • structured programming: when we use constructs like if and for
  • procedural programming: when we with procedures/functions that call each other
  • modular programming: when we combine logical structures into modules and include this into our program
  • object oriented programming: when we organise our code with objects that contain data structures and associated behaviour

Programming paradigms 1/2

A programming paradigm can help translate a specific problem into code.

Declarative programming

The code declares the desired result but not how to compute it. It describes what computation should be performed without specifying detailed state changes.

  • functional programming: where the concept of mathematical functions is used to declare the desired result as a series of function evaluations and it avoids state and mutable data

Object Oriented Programming

We organise our code with objects that contain data structures and associated behaviour. The main building block is a class, which contains:

  • constructors that take care of initialization of the data structure
  • destructors that take care of deletion of the data structure
  • (copy) operations
  • functions
  • hierarchies
  • protection of variables and functions
  • \(\ldots\)

Object Oriented Programming - C++

Basic structure class_template.cpp

class class_name {
private:
  // private variables and functions
protected:
  // protected variables and functions
public:
  // public variables and functions
};
  • private: Members can only be access or viewed from inside of the class.
  • protected: Members can only be access from within inherited classes.
  • public: Members can be access from outside the class.

Object Oriented Programming - C++ - Header

Basic structure matrix.hpp

#ifndef MATRIX_HPP
#define MATRIX_HPP

#include <iostream>
#include <vector>

class Matrix {
private:
  int rows;                              // Number of rows
  int cols;                              // Number of columns
  std::vector<std::vector<double>> data; // 2D vector to store elements

public:
  Matrix(int rows, int cols); // Constructor

  ~Matrix(); // Destructor

  void setValue(int row, int col, double value); // Set a value

  double getValue(int row, int col) const; // Get a value

  void print(std::ostream &stream) const; // Display the matrix
};

#endif // MATRIX_HPP

Object Oriented Programming - C++ - Class code

Basic structure matrix.cpp

#include "matrix.hpp" // Include the definition of our class
#include <iostream>
#include <stdexcept> // For exceptions

// Constructor
Matrix::Matrix(int rows, int cols)
    : rows(rows), cols(cols), data(rows, std::vector<double>(cols, 0.0)) {}

// Destructor
Matrix::~Matrix() {}

// Set a value in the matrix
void Matrix::setValue(int row, int col, double value) {
  if (row < 0 || row >= rows || col < 0 || col >= cols) {
    throw std::out_of_range("Index out of bounds");
  }

  data[row][col] = value;
}

// Get a value from the matrix
double Matrix::getValue(int row, int col) const {
  if (row < 0 || row >= rows || col < 0 || col >= cols) {
    throw std::out_of_range("Index out of bounds");
  }

  return data[row][col];
}

// print the matrix
void Matrix::print(std::ostream &stream) const {
  for (const auto &row : data) {
    for (const auto &value : row) {
      stream << value << " ";
    }
    stream << std::endl;
  }
}

🔁 Object Oriented Programming - C++ - Constructor/Destructor

  • Constructor: Is called during the initialization of an object and handles setting up all necessary variables. Dynamic memory allocation is performed here.
  • Destructor: Is called during the deletion of an object and takes care of cleaning up. Free dynamically allocated memory.

Operators and operator overloading

operators are used to perform operations on variables and values.

We have seen them in action already when using +, *, <<, \(\ldots\). Some operators are associated with a class, some are just friends to a class.

Operators and operator overloading - implementation

Basic structure matrix2.cpp - partially displayed

// Operator overloading: Matrix addition
Matrix Matrix::operator+(const Matrix &other) const {
  if (rows != other.rows || cols != other.cols) {
    throw std::invalid_argument("Matrix dimensions do not match");
  }

  Matrix result(rows, cols);
  for (int i = 0; i < rows; ++i) {
    for (int j = 0; j < cols; ++j) {
      result.setValue(i, j, data[i][j] + other.data[i][j]);
    }
  }

  return result;
}

// Operator overloading: Matrix multiplication
Matrix Matrix::operator*(const Matrix &other) const {
  if (cols != other.rows) {
    throw std::invalid_argument("Matrix dimensions do not match");
  }

  Matrix result(rows, other.cols);
  for (int i = 0; i < rows; ++i) {
    for (int j = 0; j < other.cols; ++j) {
      double sum = 0.0;
      for (int k = 0; k < cols; ++k) {
        sum += data[i][k] * other.data[k][j];
      }
      result.setValue(i, j, sum);
    }
  }

  return result;
}

// Overload the stream insertion operator
std::ostream &operator<<(std::ostream &os, const Matrix &matrix) {
  matrix.print(os);

  return os;
}

// Scalar multiplication (Matrix * Scalar)
Matrix Matrix::operator*(double scalar) const {
  Matrix result(rows, cols);

  for (int i = 0; i < rows; ++i) {
    for (int j = 0; j < cols; ++j) {
      result.setValue(i, j, data[i][j] * scalar);
    }
  }

  return result;
}

// Scalar multiplication (Scalar * Matrix)
Matrix operator*(double scalar, const Matrix &matrix) {
  Matrix result(matrix.rows, matrix.cols);

  for (int i = 0; i < matrix.rows; ++i) {
    for (int j = 0; j < matrix.cols; ++j) {
      result.setValue(i, j, scalar * matrix.data[i][j]);
    }
  }

  return result;
}

Things to keep in mind - operators

What happens in the following line of code?

Matrix mat3 = mat1 * 2.0;

The assignment operator is created by default and does a bitwise copy if not overloaded. It does not necessarily create a new memory block and this can cause difficulties for dynamic memory.

Matrix& operator=(const Matrix& t)

The copy constructor is created by default as well. It creates a separate memory block for the new object

Inheritance

When working with OOP it happens frequently that a cain of classes exist that get more specific with each link. To reflect this in our code we can use inheritance where one class inherits the variables and functions of another.

public:
  SquareMatrix(int dim); // Constructor
  double det();          // Determinate

Inheritance - code

Basic structure matrix3.cpp

SquareMatrix::SquareMatrix(int dim) : Matrix(dim, dim) {}

SquareMatrix SquareMatrix::subMatrix(int row, int col) {
  SquareMatrix minor(getRows() - 1);
  int minorRow = 0, minorCol = 0;

  for (int i = 0; i < getRows(); ++i) {
    if (i == row)
      continue; // Skip the specified row
    minorCol = 0;
    for (int j = 0; j < getColumns(); ++j) {
      if (j == col)
        continue; // Skip the specified column
      minor.setValue(minorRow, minorCol, getValue(i, j));
      ++minorCol;
    }
    ++minorRow;
  }

  return minor;
}

double SquareMatrix::det() {
  switch (getRows()) {
  case 1:
    return getValue(0, 0);
    break;
  case 2:
    return (getValue(0, 0) * getValue(1, 1)) -
           (getValue(0, 1) * getValue(1, 0));
    break;
  default:
    // Recursive case: Laplace expansion along the first row
    double det = 0.0;
    for (int j = 0; j < getColumns(); ++j) {
      SquareMatrix minor = subMatrix(0, j); // Get the minor matrix
      double cofactor = getValue(0, j) * minor.det();
      if (j % 2 == 0) {
        det += cofactor; // Add for even columns
      } else {
        det -= cofactor; // Subtract for odd columns
      }
    }
    return det;
  }
}

Things to keep in mind - inheritance

  • We can not access private parts of a matrix only protected or public
  • The constructor always needs to call the base as the first.
  • If we use class SquareMatrix : public Matrix the keyword public is not the only choice:
    • public inheritance: Makes public members of the base class public in the derived class, and the protected members of the base class remain protected in the derived class.
    • protected inheritance: Makes the public and protected members of the base class protected in the derived class.
    • private inheritance: Makes the public and protected members of the base class private in the derived class.
